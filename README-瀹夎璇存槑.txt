学术猫·论文工作台 V6.8.2｜长期存储增强版

一、安装到 iPhone 主屏幕
1. 将本文件夹部署到 HTTPS 网站（GitHub Pages、Cloudflare Pages 等均可）。
2. 用 iPhone Safari 打开网站。
3. 点“分享”→“添加到主屏幕”。
4. 首次正常打开并完成缓存后，核心页面可离线使用。

二、V6.8.2 这次只做长期数据安全增强
- 首页与统计进一步改成 IndexedDB 按索引、按时间范围读取；不再为了显示首页而整表载入大量历史记录。
- 搜索索引改成增量维护：新增/修改/删除一条业务记录时，只更新对应索引；仅迁移、导入、恢复或索引缺失时执行全量重建。
- 图片列表使用 createdAt / ownerCreatedAt / ownerTypeCreatedAt Cursor 倒序读取前 60 条，列表不再 getAll 全部图片元数据。
- 清除 V6.6/V6.7 已被 V6.8.2 替代的旧搜索、旧数据库初始化、旧图片管理等死代码；保留的 V6.7 字样仅用于真实旧数据库恢复兼容。

三、数据结构与兼容性
- 主数据库：IndexedDB / AcademicCatThesisDB。
- 业务 Schema 仍为 v2；IndexedDB 运行版本提升到 3，仅用于补充按需查询所需索引和派生字段，不改变论文业务数据含义。
- 章节、写作记录、文献、问题、导师修改、待办、会议、图表等为独立 object store。
- 问题/修改/待办增加活动状态索引；图片元数据增加创建时间及所属对象复合索引。
- V6.8 使用同一个 AcademicCatThesisDB，可原地升级到 V6.8.2；V6.7 旧数据库 AcademicCatThesisDBV66 仍不会自动删除，迁移失败时可用于安全恢复。
- 图片元数据/缩略图与原图 Blob 分开保存，列表只读取缩略图，打开详情时才读取原图。

四、备份与安全
- “完整备份”包含文字数据、图片、快照和回收站，并带 SHA-256 完整性校验。
- 导入完整备份前会先显示新增、相同、覆盖和冲突数量。
- 数据库升级前创建保护快照；数据库异常时进入安全模式，不直接继续写入。
- 建议关键节点同时把 .acatbackup 文件保存到 iCloud Drive 或电脑。

五、其他稳定性能力
- analytics-worker.js 承担搜索索引、统计和健康扫描。
- 图片后台哈希/缩略图处理，Worker 不可用时自动降级。
- 未保存表单草稿自动暂存 7 天。
- 页面返回栈、存储空间预警、设置页“高级”折叠继续保留。
- tests 目录提供 Worker 大数据压力测试与浏览器 IndexedDB 压力测试；index.html?selftest=1 提供主流程浏览器回归入口。

六、重要说明
V6.8.2 仍然是“本机优先”应用，不等于 iCloud 云同步。清除 Safari 网站数据、主动删除网站数据或系统极端清理都有可能影响本地数据，因此完整备份仍然重要。


V6.8.2 长期存储增强
- 自动检查 navigator.storage.persisted()，在“我的 → 长期存储保护”显示当前是否已持久化。
- 未持久化时只做轻量提示，由用户点击后调用 navigator.storage.persist()；不会反复强弹。
- 显示 navigator.storage.estimate() 的已用空间、当前配额和使用率，并按 75% / 85% / 90% 分级预警。
- 数据健康中心显示图片、快照、其他本地数据/离线缓存的占用估算。
- 完整备份超过 14 天时仅在 App 内轻提醒；成功备份后重新计时。
- IndexedDB 写入遇到 QuotaExceededError 时立即停止当前失败写入并打开存储保护入口，不会主动删除论文数据。
- App 版本升级时创建保护快照并记录当前版本；数据库 Schema 仍为 v2，IndexedDB 运行版本仍为 3。
- 持久存储不能替代异地备份。长期使用建议定期把 .acatbackup 保存到 iCloud Drive 或电脑。
